# Corrections for cs1-playset/AUDIT.md

These come from decoding the Workshop map's data asset offline (`audit/local.md`, `cs1-offline/`). AUDIT.md itself was not edited.

| AUDIT.md says | Correction | Evidence |
|---|---|---|
| "The core simulation data is compressed, so a missing string does **not** prove a mod has no data." | The data asset is **not compressed**. Its strings are delta-coded (`0x80`, UInt16 BE length, each char as the byte difference to the previous one). The mod-data dictionary decodes completely: **22 keys** in the map, listed in `audit/local.md`. A key that is absent means the mod stored nothing. | `src/extract.mjs` chains all 22 entries exactly (each ends where the next key starts). |
| `ProceduralObjects` "702 strings, incl. layers and visibility" | **690 PO objects** (425 building-based, 265 prop-based); 684 with edited meshes; **no layers** (empty `Layer[]`); visibility "Always" on all. | `out/po-offline.json` |
| Procedural Objects 1094334744 → 3071492847 "(re-upload, same `ProceduralObjects` assembly)" | Not a full drop-in. **86 objects use base prefab `1094334744.Cube_Data`.** 3071492847 ships the cube as `NativeCube_Procedural` (package 3071492847), so those 86 are **dropped on load**: the export session's AutoSave and both user saves hold 604 objects. They are 8–39 m textured blocks (Sidewalks & More cobble/sidewalk textures). Do not save the map from the editor with this playset. The offline decode keeps all 690. | `out/po-classes.md` ("paved block", loads = no) |
| `EffectsPOModule` in the mod data | It is not a separate key. The 57 PO objects based on `1251664417.Dam Electricity` each carry an Effects module and have zero size (all vertices collapsed to one point): invisible effect emitters near the falls, not geometry. | `out/payloads/ProceduralObjectsDataKey1.bin` |
| IMT block "`<IMT>` XML referencing 1889660581 and 2889685220 assets" | That is only `NodeMarkupUsedPrefabs` (114 B). The markings are in `NodeMarkup` (140 KB gzip, 1.3 MB XML): **1 160 node markings + 985 segment markings, 2 875 lines, 91 fillers**. Of these, **81.6 km of guardrail** use `1889660581.Single Steel Barrier - raisable`, plus 32.7 km of painted lines; 14 fillers use the `2889685220` Sidewalk-003 decal texture. | `out/imt-summary.md`, `out/imt-markings.geojson` |
| Prop Painter: Revisited "data-preserving (rock colours)" | The Workshop map has **no `PropPainter` key**, so there are no prop colours to preserve. The key appears only after a session with the mod enabled (AutoSave: near-empty) and in dktanew (in-game colours). | `audit/local.md`, mod-data table |
| Surface Painter "earlier painting could survive" | The map has **no `SurfaceManager` key**. The saves have one, but it is an empty grid (72 902 of 73 018 bytes = 0xFF). Enabling Surface Painter is harmless but yields nothing. | same |
| ACME "left out: … no map data" | The map has an `ACME` key (763 B, camera bookmarks). No content impact; leaving it out is fine. | same |
| Prop Control as the successor of Prop Snapping / PTA … | The map also has `PropPrecision` (22.5 KB, sub-unit prop offsets from the Prop Precision mod), which is not in the playset; the effect is centimetres. `PropScaling` is all 1.0 (no scaled props). | same |
| Tree Control "740k trees; not Tree Anarchy" | Right for loading. Note that the map also carries a legacy `TreeAnarchy` key (19 KB, mentions only Aussie Bushes) besides Tree Control's `MoreTrees`, `TreeSnapping`, `TreeScaling` (~49 400 trees ≠ 1.0) and `TreeControlAnarchyFlags`. | same |
| Theme mix 2972881605 | Confirmed. The map stores only the mix name: `THEME-MIXER-2.5` = `DakotaFalls_5dec87…` (and TM2 `ProjectMap4_5dec87…`). There is no `MapThemeMetaData` and no `mapThemeRef`. | `audit/local.md` |
