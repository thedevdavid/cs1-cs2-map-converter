  Terrain "mirror" look: a 24-bit PNG does give alpha 1.0, which very likely

  (3) Confirmed from the importer. DefaultTextureImporter loads the PNG with its
  own channel count. TextureImporter.CompressBC returns immediately unless the
  image has 8 bpp and exactly 4 channels. So our 24-bit BaseColor PNGs were not
  BC-compressed: they were stored as raw RGB, about 48 MB per 4096² diffuse, and
  the GPU samples the missing alpha as 1.0. If the shader reads diffuse alpha
  as smoothness, everything is at maximum smoothness, which is your mirror.
  (1) What the managed code shows:
  - The slots' [TextureImport] attributes: m_*Diffuse are Albedo (sRGB, BC7 when
    the image has 4 channels). m_*Normal are MaskMap (linear, BC7, isNormalMap
    false, so no normal swizzle), not a tangent normal map in the Normal mode.
  - The format switch: m_UseLegacyTextureFormat (our terrain-cs1 sets it) sets
    the shader's _TerrainLegacy{Grass,Dirt,Rock}Texture = 1. In legacy mode the
    missing-normal fallback is Texture2D.normalTexture (a plain tangent normal);
    in the new format it's the game's own packed fallback
    (m_FallbackNormalTexture). So the "normal" slot holds a tangent normal in
    legacy mode and a packed mask/normal map in the new format.
  - The shader itself is compiled HLSL and not in the DLLs, so I can't prove
    which channel is smoothness. The diffuse alpha in legacy mode (the CS1
    convention, which that mode mirrors) is by far the likeliest, and it matches
    the symptom.
    (2) Vanilla values: the vanilla terrain textures are in the game's bundles,
    not readable offline. I can read a vanilla texture's alpha through the
    bridge in a later round if you want numbers.
    Fix to try (no bridge change): re-export the 7 BaseColor PNGs as 32-bit

    because the files and hashes change), then compare one layer first, e.g.
